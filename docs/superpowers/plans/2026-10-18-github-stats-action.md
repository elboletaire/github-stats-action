# github-stats-action: implementation plan

Spec: `docs/superpowers/specs/2026-10-18-github-stats-action-design.md`. Read it first; it's the contract.

Each task runs in its own worktree and branch off `main` (`.worktrees/<branch>`), is implemented by a worker, reviewed, then merged into `main`. Task 1 goes first; tasks 2–5 run in parallel once it's merged; task 6 integrates.

References (read-only):
- `~/.claude/skills/download-stats/build_dashboard.py` and `template.html`: the current dashboard, to port.
- `~/src/manga-downloader/tools/stats-snapshot/main.go`: the old snapshot format, for the import.
- `~/.cache/download-stats/raw-*.json`: real releases API responses (concatenated arrays from `gh api --paginate`), for fixtures.
- `git -C ~/src/manga-downloader show origin/stats-data:<path>`: real old-format snapshots and `daily.csv`.

Conventions for every task: pnpm workspaces, TypeScript strict, ESM, Node 24 (`engines`), vitest, code comments 1–2 lines and only for the why, no `any` without a reason, conventional commits without Co-authored-by trailers.

## Task 1: scaffold and core (branch `feat/core`)

Files: root `package.json` (pnpm workspace, scripts: build, test, typecheck, lint-free), `pnpm-workspace.yaml`, `tsconfig.base.json`, `.gitignore` (node_modules, .worktrees, coverage; NOT dist), `action.yml`, `packages/core/**`, `packages/action/**` (entry + local CLI), `tsdown.config.ts`, `fixtures/` (trimmed real data), `.github/workflows/ci.yml`.

- `core`: config loading and validation (YAML, defaults when the file is missing, clear errors), glob matching, semver compare; collectors (releases with pagination, repo counts, stargazers backfill + incremental with `application/vnd.github.star+json`, traffic views/clones/referrers/paths, Docker Hub `https://hub.docker.com/v2/repositories/<ns>/<name>` `pull_count`) via up-fetch with an injectable fetch for tests; snapshot read/write on a directory (the checked-out data branch); traffic merge; `buildDataset()` producing the exported `Dataset` type exactly as the spec lists (periods, medians, estimated spread, measured gaps, counters, epochs, stars per day); `daily.csv`; old-format import.
- `action`: reads inputs, checks out/creates the data branch in a temp worktree with git, runs collectors, writes snapshots and derived files (`dataset.json`, `daily.csv`), commits and pushes with one retry, sets outputs. Outputs from tasks 2–4 are called through three functions with fixed signatures, stubbed for now: `renderDashboard(datasets, { mode: 'pages' | 'standalone' }) → files`, `renderCharts(dataset) → files`, `renderBadges(dataset) → files`, where `files` is `{ path: string, content: string }[]`. Put these signatures in `packages/core/src/outputs.ts`.
- Local CLI: `pnpm stats --repo owner/name --out <dir> [--config <file>] [--traffic] [--dry-run] [--import-old <dir>]`.
- Fixtures: trimmed real releases (all manga-downloader releases, only the fields the snapshot keeps), two old-format snapshots, a stargazers sample, a traffic sample; a fixture `Dataset` JSON generated by `buildDataset` for tasks 2–4.
- Verify: `pnpm typecheck && pnpm test && pnpm build`; unit tests for config, globs, semver, every Dataset field (compare periods/totals against the numbers in the current dashboard for the same data), import, traffic merge; run the CLI against `elboletaire/manga-downloader` with `--dry-run --out /tmp/gsa-run` using `GITHUB_TOKEN=$(gh auth token)` and check totals match `gh api` numbers.

## Task 2: dashboard (branch `feat/dashboard`, after task 1)

Files: `packages/dashboard/**` (vite app, TS), wiring of `renderDashboard` in `action`.
- Port every section of the current dashboard (see spec "Outputs"), generalised to N groups and configurable epochs, plus stars over time and the traffic section. Light/dark tokens, phone width (no page-level horizontal scroll at 390px), tooltips on hover and tap, the zoom strip, the per-file picker and pivot with sticky first column and table semantics.
- Two builds: Pages (`index.html` + fetch `data/<owner>/<repo>/dataset.json`) and standalone (one HTML, datasets inlined, no fetch).
- Verify: vitest for pure helpers; Playwright (playwright-core + system Chromium at `/usr/sbin/chromium`, run with `env -u DISPLAY -u WAYLAND_DISPLAY`) on both builds from the fixture Dataset: no page errors, scrollWidth == 390 at 390px, screenshots light/dark desktop/phone.

## Task 3: SVG charts (branch `feat/svg`, after task 1)

Files: `packages/svg/**`, wiring of `renderCharts`.
- Stars over time, downloads per day (measured when ≥14 measured days, else estimated, labelled), downloads per release by group with epoch markers; light and dark files; valid standalone SVG (no scripts, no external refs), fixed viewBox, readable at README width.
- Verify: vitest snapshot-free checks (well-formed XML, expected series counts, no NaN), render each SVG in Chromium to PNG and look at them.

## Task 4: badges (branch `feat/badges`, after task 1)

Files: `packages/badges/**`, wiring of `renderBadges`.
- shields.io endpoint JSON (`schemaVersion: 1`, label, message, color) and flat standalone SVG badges for: total downloads, per group, latest release downloads, stars, Docker pulls, each counter. Compact number formatting (12.2k).
- Verify: vitest on formatting and JSON shape; text width estimation sane; render a few SVGs in Chromium.

## Task 5: action packaging and docs (branch `feat/action`, after task 1)

Files: `action.yml` (final inputs/outputs), `README.md` (what it does, privacy, PAT for traffic, Pages example workflow, config reference, import from the old format), `examples/stats.yml` (manga-downloader's config), `.github/workflows/ci.yml` (typecheck, test, build, dist up to date), the dist build.
- Verify: `pnpm build` produces `dist/index.js` and `dist/dashboard/`; CI workflow lint with `actionlint` if available; README examples match `action.yml`.

## Task 6: integration (after 2–5 are merged)

- Merge order 2, 3, 4, 5 into `main`; rebuild `dist/`.
- Full local run: CLI against `elboletaire/manga-downloader` with the import of the real old `stats-data` branch into a temp dir, then all outputs; open the standalone dashboard and the SVGs and compare numbers with `~/.cache/download-stats/dashboard.html`.
- Integrator review of the whole.
